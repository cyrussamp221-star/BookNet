# BookNest — learning starter
Use Node 22+ and VS Code. Open two terminals. In the first: cd backend, npm install, copy .env.example .env (Windows), npm start. In the second: cd frontend, npm install, npm run dev. Open localhost:5173. Register, sign in, browse and add books. Covers are original placeholder graphics. Data is persisted in backend/data.json; not production-grade storage.
AI: install Ollama from its official site, run `ollama pull llama3.2:1b`, then ensure Ollama is running. The backend calls Ollama and validates returned IDs against its catalog. Hosted backend needs a reachable AI service, not localhost.
Maya: use instructor-provided sandbox credentials only. Put public and secret sandbox keys in backend/.env, restart. No real payments. Checkout creates a pending order and redirects to hosted sandbox. Return page requests server verification; gateway response schema and sandbox behavior must be tested with instructor credentials. No webhook implemented; verification is manual. Do not deploy for real sales: stock reservation, webhook reconciliation, durable database and security hardening are outstanding.
Deployment: deploy backend separately to Render (root backend, npm install, npm start); configure env vars and persistent database/storage. Deploy frontend to Netlify (root frontend, npm run build, publish dist), set VITE_API_BASE_URL to backend HTTPS URL plus /api/v1. Set backend FRONTEND_URL to Netlify origin. Never commit .env. 
PWA: npm run build then npm run preview (set FRONTEND_URL to preview origin for API access). Browse books online, then use DevTools offline and reload. Verify manifest and service worker. Test 360x800,390x844,412x915,800x600. Run mobile Lighthouse on deployed site: performance >=75, accessibility >=85, best practices >=85, SEO >=80; verify installability separately if Lighthouse version lacks PWA score. Submit actual audit, URLs and 2–3 minute recording. No scores claimed. 
Learning tasks: split page module into separate lazy chunks, add field-level errors, sticky checkout actions, category drawer, explicit auth/cart/network contexts, improve order reconciliation and stock reservation. Explain useState, useEffect cleanup, props, context, controlled forms, router, list keys, service worker and server-authoritative pricing. API endpoints are in backend/server.js. This is a starter, not a verified final submission.
